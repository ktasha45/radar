# Radar 연결과 기록 계약

## 저장소 선택과 맥락

사용자가 지정한 Radar 저장소, 현재 작업 공간의 프로젝트 지도, 기존 설정을 우선한다. 이 작업 공간의 기본 위치는 `/home/dongykim/llm/radar`이다. 경로가 없으면 무관한 디렉터리를 일괄 색인하거나 새 저장소를 만들지 않는다. 저장소 접근 없이도 조사는 진행하고 저장할 곳만 필요할 때 확인한다.

작업 전에 `AGENTS.md`, `docs/user-context.md`, 관련 `docs/workflow.md`, `data/opportunities.csv`, `data/evaluations.csv`, `data/intake/`, 최근 관련 `reports/daily/`를 읽는다. 존재하면 `docs/user-private.local.md`와 `data/user-decisions.local.jsonl`도 읽는다. 현재 대화의 명시적 정정이 과거 추정보다 우선이다. 비공개 파일이 없다는 것은 사용자의 일정·선호가 없다는 뜻이 아니다.

기존 Git 변경을 보존하고 변경 전 현재 브랜치·원격·상태를 확인한다. 이 Radar는 `git pull --ff-only`, 검증 후 이번 작업만 명시적 stage/commit/push하는 운영이다. 충돌이나 인증 실패를 숨기지 않는다. 다른 저장소에 이 규칙을 전파하지 않는다.

## 세 위치의 역할

새 데이터베이스를 병렬로 만들거나 매번 schema를 바꾸지 않는다.

| 위치 | 기록 |
| --- | --- |
| `data/opportunities.csv` | 현재 공식 상태·일정·마감·형식·자격·비용·지원·출처·확인일·다음 행동. 길어지는 대상/선수지식/서류는 `notes`에 핵심과 날짜별 보고 위치를 연결 |
| `data/evaluations.csv` | 기존 필드로 학술 적합성·현지 경험·경쟁·준비 부담·우선순위·근거·평가일. 추가 판단 축은 rationale와 보고서에 설명 |
| `reports/daily/YYYY-MM-DD.md` | 사실의 근거와 확인 범위, 변화 전후, 모든 요구사항·준비물, A/B/C/D/대회·공모 분류, 다차원 판단, 긴급성, 문의 경로, 미확인 사항, 다음 행동 |

동일 날짜에 보고서가 있으면 주제·실행 시각을 구분해 추가하고 이전 기록을 덮지 않는다. 공개 항목에는 개인의 학교·교환/비자 일정·지원/참가 선택·연구 내부정보를 넣지 않는다. 프로그램의 공개 요건 자체는 기록한다.

### 항목 식별과 상태

- URL·정규화한 제목·연도/회차·부속 트랙을 비교한다. 기존 ID를 유지한다. 새 회차는 기존 저장소의 관례를 따르고 이전 회차를 소리 없이 덮거나 ID를 일괄 바꾸지 않는다.
- `apply`: 모집 열림/신청 검토 가능. **사용자 지원 결정이 아니다.**
- `watch`: 다음 공고·등록·지원 대기. 전년도 조건으로 현재 자격/비용을 확정하지 않는다.
- `attend`: 청강·시청 경로. `committed`는 이미 확인된 확정 상태를 추정으로 만들지 않는다.
- `closed`: 공식 마감/정원 종료. 관심 없음·개인 보류를 이 상태로 바꾸지 않는다.
- `review`: 공식 확인 불가·충돌·불명확한 현재 모집 상태. 접근 실패만으로 종료라 하지 않는다.
- 프로그램 자체의 종료, 신청 종료, 장학 종료, 논문 종료를 분리한다. `deadline`에는 이번 행동의 주 마감, 다른 마감/시간대는 notes와 보고서에 둔다.

### 매 항목의 근거 카드

짧은 항목은 한 단락이나 표로 합쳐도 되지만 다음 정보를 빠뜨리지 않는다.

> 정확한 제목·회차 / 주최자·공식 URL·확인일 / 참가 유형 / 현재 모집 상태와 무엇이 바뀌었는지 / 일정·장소·온라인 / 대상·학부생 진입 경로·선수지식 / 신청·등록·장학·초록/논문별 마감과 시간대·긴급성 / 참가비·항공·숙박·식사·지원금·지급시점 / 실제 요구 서류·분량·추천인 / 지적 적합성·교육 가치·접근성·비용·일정·교류/연구 가치와 한계 / 구체적 다음 행동·문의 경로·미확인 사항.

학술 요구 수준과 학생의 학적 제한을 혼동하지 않는다. 적합성은 해석이고 공식 조건은 사실임을 구분한다. 순위·선발률을 증거 없이 수치화하지 않는다. 결과표보다 지금 할 행동을 먼저 설명한다.

## 개인 정보와 사용자 결정

현재 배경·일정·비용 조건·정정은 `docs/user-private.local.md`, 기회별 결정은 `data/user-decisions.local.jsonl`에 저장하고 Git 제외를 확인한다. 개인 파일은 skill 패키지에 복제하지 않는다. 사용자에게 지원/참가 의사를 확인하지 않고 관심을 확정 상태로 바꾸지 않는다.

결정 JSONL 필드: `date`, `opportunity_id`(일반 맥락이면 null), `scope`, `kind`(`priority/interest/decision/application_status/fact/constraint`), `value`, `certainty`(`confirmed/tentative/unknown`), `source`. 같은 대상·범위·종류의 최신 확인을 사용하고 과거 이력을 삭제하지 않는다. 다른 컴퓨터의 로컬 기록을 자동 수집한다고 말하지 않는다.

## 변화분과 알림

직전 관련 보고/현재 행과 비교해 등록 개방·새 마감·지원·프로그램·자격·장소/일정·임박 단계 변화를 기록한다. 이번에 처음 발견한 오래된 공고도 새로 실행할 행동이 있으면 `새로 발견`으로 보고할 수 있다. 단순 확인일 변경은 사용자에게 새 기회 알림을 보낼 근거가 아니다.

기존 후보 재정리를 요청받으면 같은 항목을 보여줄 수 있으나 새 발견/변경과 분리한다. 넓은 예약 실행은 새롭거나 새로 긴급하거나 새로 실행 가능한 변화만 알린다. URGENT/VERY URGENT의 각 단계는 최초 진입만 알리고 자료 보완 등 다른 변화가 있으면 그 이유로 다시 알린다.

## 검증과 완료

PowerShell이 있으면 `pwsh -NoProfile -File scripts/validate.ps1`을 실행한다. 없으면 아래 표준 라이브러리 검사를 사용한다. 이것은 원본 검사를 포함하되 CSV 행 길이·실제 날짜·평가 열도 확인하며, 링크 본문 사실이나 자격 판정은 검증하지 않는다.

```bash
python3 /path/to/research-opportunity-radar/scripts/validate_radar.py --root /path/to/radar
git diff --check
```

개인 파일이 추적/스테이징되지 않았는지와 외부 페이지 내용이 사적 지침처럼 섞이지 않았는지 검토한다. 이번 공개 파일만 stage/commit/push하고 fetch 후 HEAD와 해당 원격 추적 브랜치를 비교한다. 기존 변경과 실패가 남으면 구별해서 보고한다. 의미 있는 내용 변화가 없으면 빈 보고서·빈 커밋을 만들지 않는다.

직접 요청의 최종 응답은 조사 결과·공식 링크·왜 맞는지·마감/준비물/다음 행동을 자체로 이해할 수 있게 제공하고 기록·동기화 완료 여부를 짧게 알린다. CSV나 내부 위키를 열어 보라고 답을 대신하지 않는다. skill 생성/사용은 기존 예약 작업을 생성·수정하거나 실행 상태를 확인하는 행위가 아니다.
